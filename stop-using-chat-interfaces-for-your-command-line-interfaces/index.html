Stop using chat interfaces for your command line interfaces!

Artifical Intelligence / July 1, 2025 • 4 min read
Tags: mcp automation tool calling cybersecurity workflow automation

I believe people are using MCP services incorrectly and using AI incorrectly when integrating with their cybersecurity tools, or perhaps tools in general, but specifically cybersecurity tools. Instead of creating a new interface to control your tools, meaning instead of using the normal command line, people now use MCP servers and e.g. Claude to issue commands. So they go to Claude/ChatGPT/X, write in natural language what they want to achieve, and Claude maps the intent to the correct tool and executes it, perhaps with some analysis, formatting, or summarization of the results.

This is fine, but for cybersecurity tools, wouldn’t it be better if, instead of simply issuing commands and using Claude or similar web interfaces as a new interface - why not use AI as an assistant within the workflow and workspace? So you execute your tools as normal. For example, when you’re doing large-scale recon, you may find technologies that you don’t know about. Of course, you can talk to AI anyway, but if you encounter unknown technologies, you simply ask the AI to research them for you. But here’s the thing: the AI could be connected to your workspace, so whatever you ask it to do, it can save the results to your workspace.

For example, if you’re doing recon where you encounter something new and need to do some scripting, or need to extract, transform, and load something, then you simply ask the AI to do that and give it the data. It can write the script, run the script in a sandbox, and then take the result and put it in your workspace. This could be done in a few ways, for example, your AI could be integrated as a menu when you right-click an item in your workspace. Consider a file containing lots of URLs, what if you just right-click the file, choose “Query AI” which pops up a prompt window where you can issue your command. The AI will complete the task and the result will be saved directly to your workspace. A notification can even be sent via the notification area in your OS.

Even better, if you can directly issue commands via speech-to-text; you never leave your workspace and the flow keeps flowing. This would require tighter OS integration, but the results would be magnificent. For example, if the AI knows what files or text you have selected, or what tools you are running, the more integrated the AI becomes and the more context it has which it can use to assist you.

If you say, “Okay AI, I just added a new security finding to the list,” then the AI understands the context and can say, “Oh great, I can format it and add it to the report. Do you want me fix that for you?” - And b00m, the AI runs a background task to update the report, while you continue working.

That is the goldmine here. That is what we want to achieve.

If you had access to a vulnerability database, and you notice e.g. WordPress 3.4 in your recon data, you simply ask your AI “hey, found WordPress 3.4, can you return all CVEs for that version”. The AI would immediately return the information to you, directly to your workspace, or add it your report. Your assistant is always there, ready to receive instructions, and always connected.

I think that is the direction we should go in cybersecurity, and not simply use the chat interface as an interface for our tooling. Instead, we should actually use it as an assistant, preferably through speech-to-text. Using voice is much more natural than alt-tabbing to ChatGPT or Claude and typing out a formal command. Voice preserves the flow state that chat interfaces destroy.

Apart from talking to your assistant, another crucial point is: I believe the AI assistant should be connected to your workspace. So whatever you ask it to do, if you ask it to do something that returns results, the AI can return the results to your workspace. So you have all the findings in your workspace. That’s what we want to achieve.

Sure, you could build MCP tools that save to your workspace. But you’re still typing commands in a chat window instead of having AI seamlessly integrated into your actual workflow. Additionally, voice transforms AI from a tool you go to into an assistant that’s with you. It’s the difference between:

  • Stop → Type → Wait → Resume
  • Just speak while working → Get results in your workspace

I think my main issue here is that people are using chat interfaces as an interface for their tooling, which to me is - why are we simply substituting one interface for another? That doesn’t make any sense for me. Technically, we just run commands. If you have a pipeline, you already have a state machine. Why do you need an AI interface with that? Doesn’t make sense.

So next time you’re about to type a command into ChatGPT, ask yourself: why am I using this as an interface instead of having it work alongside me? Your workflow is waiting for an upgrade.
